# Матрица трассировки 

## 1. Легенда

- **US** — User Story, **JS** — Job Story, **UC** — Use Case (из `02_Requirements`).
- **As-is / To-be** — модели процессов из `03_BPMN_Processes`.
- **Seq** — диаграмма последовательности из `05_Sequence diagram`.
- **API** — метод из `06_REST API`.

## 2. Функциональные требования

| ID | Требование | Стейкхолдер | Процесс (BPMN) | Sequence | API-метод | Критерий приёмки |
|---|---|---|---|---|---|---|
| **US-01** | Просмотр активных подписок | Пользователь | — |  | `GET /subscriptions/active` | Список возвращается за ≤ 2 с; отображаются тариф, дата окончания, статус |
| **US-02** | Просмотр истории платежей | Пользователь; Финансовый отдел | — |  | `GET /payments/history` | История доступна за ≤ 2 с; видна сумма, дата, статус платежа |
| **US-03** | Смена тарифа | Пользователь | `Смена тарифа.png` (to-be) | `смена тарифа.png` | `POST /subscriptions/change-tariff` | Тариф меняется; платёж инициируется на разницу; при ошибке платёжа тариф не меняется |
| **US-04** | Отключение подписки | Пользователь | `Отключение подписки.png` (to-be) | `отмена подписки.png` | `DELETE /subscriptions/{id}` | Подписка отключается; доступ сохраняется до конца оплаченного периода |

| **JS-02** | «Когда я отключаю подписку, я хочу видеть, до какой даты сохранится доступ, чтобы планировать переход на другой сервис» | Пользователь | `Отключение подписки.png` | `отмена подписки.png` | `DELETE /subscriptions/{id}` | В ответе и в UI явно указана дата окончания доступа |

| **UC-02** | Обработка успешного платежа | Финансовый отдел | — |  | `POST /payments/callback/success` | Подписка обновлена; в истории платежей — статус `success` |

## 3. Нефункциональные требования

| ID | Требование | Связано с | Метрика / критерий | Метод проверки |
|---|---|---|---|---|
| **NFR-PERF-01** | Время отклика списка подписок | US-01 | p95 ≤ 2 с | Нагрузочный тест  |
| **NFR-PERF-02** | Время отклика истории платежей | US-02 | p95 ≤ 2 с | Нагрузочный тест  |
| **NFR-PERF-03** | Время инициации платежа | UC-01 | p95 ≤ 3 с | Интеграционный тест с платёжным шлюзом |
| **NFR-SEC-01** | Аутентификация при доступе к ЛК | Все | Запрос без токена → 401 | Тест-кейс |
| **NFR-SEC-02** | Разграничение доступа «свой — чужой» ресурс | US-03, US-04 | Запрос чужой подписки → 403 | Тест-кейс |
| **NFR-SEC-03** | Идемпотентность платёжных callback-ов | UC-02 | Повторный callback не создаёт двойного списания | Тест на повторный запрос |
| **NFR-DATA-01** | Согласованность статусов платежа и подписки | US-03, UC-01, UC-02 | При `success` → подписка обновлена; при `fail` → тариф не меняется | Интеграционный тест |
| **NFR-USA-01** | Понятность итоговой стоимости при смене тарифа | JS-01 | Пользователь называет итоговую сумму до подтверждения | Юзабилити-тест |
| **NFR-OBS-01** | Логирование платёжных операций | UC-01…UC-04 | В логах — requestId, userId, сумма, статус | Проверка логов |

## 4. Бизнес-правила

| ID | Правило | Связано с | Где соблюдается | Критерий проверки |
|---|---|---|---|---|
| **BR-01** | При смене тарифа пересчёт пропорционален остатку периода | US-03, JS-01 | Сервис расчёта | Сумма = (новый − старый) × остаток/период |
| **BR-02** | При отключении доступ сохраняется до конца оплаченного периода | US-04, JS-02 | Сервис подписок | Дата окончания не меняется при отключении |
| **BR-03** | Платёж не проводится дважды при повторном callback | UC-02 | Платёжный сервис (idempotency key) | Повторный callback → 200 без нового списания |
| **BR-04** | Скидка применяется только при выполнении условий  | UC-03 | Сервис платежей | Платёж без условий — без скидки |
| **BR-05** | Пользователь не может управлять чужой подпиской | US-03, US-04 | API (authorization) | Запрос чужой подписки → 403 |
